# 새 PC 베타 확인 목록

이 목록은 배포 ZIP을 새 PC에서 압축 해제한 뒤 수행합니다. 기존 개발 PC의 모델·Python·설정이 없는 상태를 기준으로 확인합니다.

1. `extension/`을 로드하고 Paper Translator 이름을 확인합니다. 원본 MouseTooltipTranslator는 비활성화합니다.
2. 설정의 세 실행 선택이 각각 저장·복원되는지 확인합니다. 번역 주소 변경이 임베딩·Docling 주소를 바꾸지 않아야 합니다.
3. 번역 API + 임베딩 API + 서버 Docling으로 연결 확인 후 논문 한 페이지를 번역합니다. 로컬 도우미를 설치하지 않고도 동작해야 합니다.
4. 임베딩만 브라우저 실행으로 바꿔 해당 모델을 준비하고 같은 문서를 번역합니다. 반대 조합도 확인합니다. 원하지 않은 모델 다운로드가 자동으로 시작되지 않아야 합니다.
5. Docling 도우미를 설치하고 로컬 분석 준비·중지·자동 시작을 확인합니다. 기존 도우미가 있다면 그대로 남아 있어야 합니다.
6. ZIP 안의 `doc/beta-smoke.pdf`와 실제 두 단 논문을 각각 엽니다. 페이지 전환, 문장 연결, 캡션·수식·표 표시를 확인합니다.
7. 번역문과 원문 마우스오버·클릭, 변수 툴팁, 옵션 켜기/끄기, 패널 크기 변경을 확인합니다.
8. 영역 분류·제외·경계·분할을 저장하고 PDF를 다시 열어 반영을 확인합니다.
9. 문장과 섹션 제목에서 재번역 세 가지·복원을 확인합니다. 잘못된 서버 주소로 바꿨을 때 오류가 보이고 기존 번역은 유지되어야 합니다.
10. 문서를 다시 열어 분석·임베딩·번역 캐시가 재사용되는지 확인합니다. 임베딩 모델·주소를 바꾸면 이전 벡터와 섞이지 않아야 합니다.
11. 중지·설정 변경·탭 닫기·확장 새로고침 중 요청이 취소되고 이후 재시도되는지 확인합니다.
12. 로컬 파일 선택과 웹 PDF 자동 전환을 확인하고, 일반 웹 페이지에서 툴팁·음성·자막 기능이 실행되지 않는지 확인합니다.

브라우저 WebGPU와 실제 Chrome Native Messaging은 Node 단위 테스트로 확인할 수 없습니다. Windows/Linux 설치기는 해당 OS에서도 실행 검증해야 합니다. 서버 동시 사용량과 대용량 PDF 처리 시간은 별도로 측정합니다.

자동 검사에는 `npm test`와 `npm run build`를 사용합니다. Python 도우미 검사는 `requirements-docling.txt`를 설치한 환경에서 `python -m unittest discover -s tools -p "test_*.py"`로 실행합니다. 모델·라이브러리 버전을 포함한 서비스 식별값을 검사하므로 Docling이 없는 기본 Python에서는 일부 서버 테스트를 실행할 수 없습니다.
